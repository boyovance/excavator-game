### 人工驗收固定存檔

`npm run demo:manual` 會先核對打包 EXE 和 asar 是否與通過 `npm run test:exe` 的檔案完全一致，再啟動 `artifacts/release/manual-profile`。這是持續保留的隔離存檔，名稱初始為「M5獨立驗收」；重跑不覆蓋進度，不讀寫正式 `%APPDATA%/excavator-game`，沒有快轉或偵錯入口。由托盤打開車庫／退出。不需再次安裝。若重新打包，必須重新跑 EXE 測試後才可用。

下次使用者方便時配合一次真實短測（本輪不自動觸發睡眠）：

1. 開固定驗收存檔，派遣廢料場，記下開始時金幣與倒數；先不要領取。
2. 用 Windows 選單手動睡眠，約 5 分鐘後喚醒。觀察挖掘機位置、工作是否顯示待領取，是否出現完成通知（系統勿擾可能攔截）。
3. 點通知或從托盤打開車庫，領取一次，記下金幣與結果；從托盤退出，再執行同一命令重開，確認結果保存且不可重複領取。
4. 回報是否通過；若不符，提供畫面與操作步驟。通知／勿擾、拖曳邊緣、縮放後的觀感再依實際設備分項確認，不要求現在連續完成所有人工項。

資源數據位於 `artifacts/release/source-metrics.json` 與 `packaged-metrics.json`。首次源碼採樣期間：進程 CPU 百分比合計約 0～3.0%，工作集合計約 858～873 MiB。條件為車庫開啟、桌面視窗隱藏，場景最後恢復執行；只是該測試當下數據。工作集相加可能重複計入共享頁，不等於獨佔實體記憶體。需另做可見／隱藏、不同解析度與數小時測量才能評估常駐成本。

重現：先 `npm ci`，依次 `npm test`、`npm run build`、`npm run smoke`、各 `test:dispatch/catalog/growth/balance`、`npm run test:release`、`npm run dist`、`npm run test:packaged`。UI 腳本需要 Windows 桌面工作階段。CI 加入發佈流程及封裝資源測試，但本機成功不等於遠端 CI 已執行完畢。

## 首輪體驗驗收（新手流程與維修提示已確認）

執行 `npm run demo:release`，從歡迎頁命名與現有 2D 外觀開始。這是全新隔離存檔，使用正式 5～120 分鐘工時，並非之前快轉沙盒；不會自動派遣或領獎。試玩期間從托盤退出，正式進度不受影響。

1. 首次引導能否順利完成、找到派遣和圖鑑？
2. 派遣顯示的收入、耐久門檻與實際領取是否一致？
3. 低耐久時，免費休息／付費維修的選擇是否清楚？
4. 關閉後重新打開測試存檔時，是否保留預期進度？（`demo:release` 每次建立新存檔；後續人工重啟驗收改用上方 `demo:manual` 固定隔離存檔。）
